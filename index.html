      Introduction

      VoiceLink, by Elision Group, is a telephony infrastructure platform that connects voice bots to real phone networks in India — handling number provisioning, call routing and account management so your bot only has to handle the conversation.

      ℹ️
      Key features
      • SIP Trunk and WebSocket connectivity for inbound and outbound voicebot calls
      • DID provisioning, purchase, renewal and release across Toll-Free, Mobile and Landline series
      • Reseller and client account management with wallet, billing and KYC workflows
      • Call routing, outbound lead queueing and full call-log detail retrieval
      Base URI
      Base URL
      https://app.voicelink.co.in/api/v1
      📌
      Authentication Authenticated endpoints use a Laravel Sanctum Bearer token: Authorization: Bearer {access_token}. Public endpoints (signup, login, password reset) need no token.

      Known gaps / items to confirm

      ⚠️
      Do not let an AI guess The items below are inconsistencies or unspecified behavior in the source API descriptions. Rather than silently resolving them, we surface them here so you can confirm the correct behavior with VoiceLink before an AI coding agent implements against an assumption.
      • Outbound routing values: API descriptions say outbound supports 2=SIP Trunk, 3=WebSocket Bot, 4=Only Answer and Mobile is invalid, but List Routing / Purchased DID sample responses show for_outbound_call=1 with label Mobile.
      • Request-required DID series wording differs across supplied descriptions: some say 140/160, others 140/180. Use GET /reseller/did-types at runtime and confirm catalog naming.
      • Create WebSocket Bot: prose says reseller client_id is optional, parameter table says mandatory. Confirm before strict validation.
      • Create/Confirm purchase says auto-renew is mandatory for active purchases; renewal guards and DID release may force it off server-side. Documented here as a server-enforced exception, not a user toggle.
      • Update Client wallet_balance semantics are not explicit (replacement vs increment). Use allocate-wallet for explicit balance transfer.
      • KYC Final Submit definition contains no client_id parameter even though earlier KYC steps support reseller-on-behalf-of-client. Confirm how client KYC final submission is performed.
